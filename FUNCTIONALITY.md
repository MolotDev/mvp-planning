# Функціональність MVP

Опис поточного функціоналу веб-додатку операційного планування: вогневі завдання, політні заявки, пуски, звіти та каталоги. Інтерфейс українською. Маршрутизація через `HashRouter` (адреси з префіксом `/#/`).

Документ структурований **за сторінками**. Для кожної сторінки окремо вказано можливості ролей **Центр**, **Загін** і **Екіпаж**.

---

## Ролі та доступ

| Роль | Код | Домашня сторінка |
| --- | --- | --- |
| Центр | `CENTER` | `/planning/missions` |
| Загін | `DETACHMENT` | `/planning/tasks` |
| Екіпаж | `CREW` | `/planning/launches` |

### Матриця доступу за областями

| Область | Центр | Загін | Екіпаж |
| --- | --- | --- | --- |
| Вогневі завдання (місії) | повне керування | немає доступу | немає доступу |
| Політні заявки | перегляд усіх | повне керування своїми | немає доступу |
| Пуски | перегляд усіх | перегляд своїх | редагування своїх полів |
| Звіти | перегляд усіх | повне керування своїми | немає доступу |
| Цілі | повне керування | повне керування | немає доступу |
| Засоби | немає доступу | повне керування | немає доступу |

**Обмеження екіпажу в пусках** — лише поля: номер маршруту, серійний номер засобу, серійний номер трекера, боєприпас, кількість боєприпасу.

**Область видимості даних**

- **Центр** — усі загони / усі сутності.
- **Загін** — лише свій `organization_id` (фільтр загону зафіксований).
- **Екіпаж** — лише бойові групи, де він ведучий або підтримуючий (фільтр екіпажу зафіксований).

Пункти меню без доступу залишаються видимими, але не відкриваються (підказка «Відхилено в доступі!»).

## Наскрізні можливості

Спільні для кількох сторінок механіки:

- **Вхід** без пароля; сесія в `sessionStorage`.
- **М’який архів** (`archived_at`) — записи не видаляються фізично з домену місій / заявок / цілей / засобів.
- **Статуси життєвого циклу:** активний → виконано (`reported_at`) → підтверджено (`confirmed_at`) / архів; окремо статуси скасування.
- **Скасування виконання** (сценарії): до виїзду; без пусків; частково виконано. План розподілу при скасуванні зберігається; трекери повертаються в пул (крім витрачених).
- **Пул трекерів** `TRK-01`…`TRK-40` (`available` / `assigned` / `expended`); пошук у селекторі; зайнятий трекер не показується іншим пускам.
- **Підтвердження ВЗ центром** блокує редагування пов’язаних звітів; **«Дозволити редагування звіту»** знімає підтвердження і знову відкриває подані звіти як чернетки.
- **Скидання до початкового стану** у бічній панелі відновлює доменні дані (включно з пулом трекерів) без виходу з сесії.
- **Синхронізація вкладок** через `BroadcastChannel`.
- Збереження наряду / подання звіту додатково пише в Supabase (якщо налаштовані змінні середовища).

## 1. Вхід — `/login`

**Призначення:** вибір ролі та початок сесії.

### Центр
- Вхід однією кнопкою.
- Після входу — на сторінку вогневих завдань.

### Загін
- Вибір загону зі списку → сесія з `entityId` загону.
- Після входу — на політні заявки.

### Екіпаж
- Вибір екіпажу зі списку → сесія з `entityId` екіпажу.
- Після входу — на пуски.

Якщо сесія вже є — автоматичний перехід на домашню сторінку ролі.

---

## 2. Вогневі завдання — `/planning/missions`

**Призначення:** планування та огляд вогневих завдань центру.

**UI:** пошук, діапазон дат, фільтр статусів (у т.ч. «Скасовані»), режими «по добах» / «по цілях», метрики, сітка карток, створення ВЗ.

### Центр
- Перегляд усіх місій.
- Створення, редагування, архів / відновлення (де передбачено потоком).
- Відкриття картки місії.
- Перехід до заявок із контекстом цілі / дати.

### Загін
- Немає доступу до маршруту.

### Екіпаж
- Немає доступу до маршруту.

---

## 3. Картка вогневого завдання — `/planning/missions/:missionId`

**Призначення:** деталі ВЗ, розподіл по цілях, готовність, підтвердження / unlock, скасування.

**UI:** шапка зі статусом, дошка розподілу / форма, панель готовності, аналітика, модалки підтвердження та скасування.

### Центр
- Перегляд і редагування (поки немає блокування плануванням / звітом / підтвердженням).
- Підтвердити виконання (коли всі пов’язані звіти подані).
- Дозволити редагування звітів (зняти підтвердження).
- Скасувати виконання.
- Перехід до пусків місії.

### Загін
- Немає доступу.

### Екіпаж
- Немає доступу.

---

## 4. Політні заявки — `/planning/tasks`

**Призначення:** календар / сітка політних заявок загонів.

**UI:** пошук, дати, статус (у т.ч. «Скасовані»), фільтр загону (лише для центру), режими «по добах» / «по цілях», картки заявки.

### Центр
- Перегляд заявок усіх загонів.
- Фільтр за загоном.
- Відкриття заявки (без редагування розподілу).
- На картці для скасованих до виїзду — без кнопок «Пуски» / «Звіт».

### Загін
- Лише заявки свого загону.
- Створення заявки на сьогодні / майбутню дату (`/planning/tasks/new?date=…`).
- Відновлення з архіву (де доступно).
- Перехід до розподілу, пусків, звіту (з урахуванням статусу скасування).

### Екіпаж
- Немає доступу.

---

## 5. Картка політної заявки — `/planning/tasks/:taskId` (і `new`)

**Призначення:** план цілей / ТП / засобів, розподіл екіпажів, перегляд пусків, перехід до звіту, скасування.

**UI:** робоча зона розподілу, підсумки пусків, статистика екіпажів, модалка деталей пуску, шапка зі статусом і діями.

**ТП:** для `MP00` завжди підпис «Основна ціль»; для інших кодів — лише код без додаткової назви.

### Центр
- Перегляд заявки.
- Скасування виконання.
- Перегляд поданого звіту (якщо є).
- Без створення / редагування плану розподілу.

### Загін
- Створення нової заявки (доба, цілі, ТП, засоби, екіпажі).
- Редагування активного плану і збереження (локально + публікація наряду в Supabase).
- Перехід до звіту (приховано для статусу «Скасовано (до виїзду)» з поясненням, що звіт не подавався).
- Скасування виконання.
- Перегляд / робота з деталями пусків у межах заявки.

### Екіпаж
- Немає доступу.

---

## 6. Пуски (список) — `/planning/launches`

**Призначення:** наряд пусків у режимах карток (по БГ / по заявці) або таблиці.

**UI:** пошук, дати, статус, фільтр загону / екіпажу (залежно від ролі), перемикач режиму перегляду.

### Центр
- Перегляд усіх пусків.
- Фільтри загону та екіпажу.
- Відкриття наряду групи / заявки / місії.
- Без редагування полів пуску.

### Загін
- Перегляд пусків свого загону.
- Фільтр загону зафіксований.
- Відкриття наряду (перегляд).
- Без редагування полів екіпажу.

### Екіпаж
- Лише свої бойові групи.
- Фільтр екіпажу зафіксований.
- Відкриття наряду для редагування дозволених полів.

---

## 7. Наряд пусків — `/planning/launches/:battleGroupId`, `/task/:taskId`, `/mission/:missionId`

**Призначення:** деталі пусків групи / заявки / місії; спорядження борту.

**UI:** таблиці / секції за цілями, екіпажами, ТП; селектор трекера з пошуком; перемикач режиму редагування для екіпажу.

Відображення ТП береться з алокації заявки (код `MP##`), навіть якщо точки немає в каталозі.

### Центр
- Повний перегляд наряду.
- Без увімкнення редагування полів екіпажу.

### Загін
- Перегляд наряду свого загону.
- Без редагування полів екіпажу.

### Екіпаж
- Перегляд і редагування лише своїх груп (ведучий / підтримка).
- Зміна: маршрут, серійник засобу, трекер, БЧ, кількість БЧ.
- Збереження в локальне сховище з публікацією в Supabase.

---

## 8. Звіти (список) — `/reports`

**Призначення:** денні звіти загонів.

**UI:** дата, пошук, статус (`Чернетка` / `Подано` / `В архіві`), фільтр загону (центр), метрики, створення звіту, картки звітів.

### Центр
- Перегляд звітів усіх загонів.
- Відкриття документа.
- Без створення / редагування / подання / архівування.

### Загін
- Лише звіти свого загону.
- Створення звіту на дату.
- Відкриття / редагування чернетки (або розблокованого після дозволу центру).
- Архівування чернетки (де передбачено).

### Екіпаж
- Немає доступу.

---

## 9. Документ звіту — `/reports/:reportId`

**Призначення:** заповнення фактичних подій і порядку пусків, подання звіту, скасування доби.

**UI:** шапка зі статусом; секція подій (+ додати подію); таблиця пусків (час, маршрут, трекер, результат тощо); кнопки очистити / подати / скасувати виконання.

**Подання:** усі екіпажі мають подію «Повернення»; у пусків — коректні результати / причини проблем.

**Після дозволу центру на редагування:** загін знову може змінювати й подавати звіт незалежно від попереднього статусу «Подано» (після unlock звіт повертається до чернетки).

**Скасовано (до виїзду):** без чернетки / без додавання подій / без подання; поля лише для читання.

### Центр
- Перегляд документа.
- Без редагування, подання, очищення, скасування доби зі звіту.

### Загін
- Редагування чернетки / розблокованого звіту свого загону.
- Додавання / зміна подій і даних пусків.
- Очищення чернетки, подання звіту.
- Скасування виконання доби (поки доступно).

### Екіпаж
- Немає доступу.

### Центр

### Загін
